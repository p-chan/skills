# Markdown

Markdown は、描画する環境によって解釈が異なる。CommonMark だけで描画される環境は少ないため、GFM などの拡張が有効な環境も含め、意図どおりに表示される書き方をする。

出力先のツールやサービスが記法を指定している場合は、その指定に従う。

## URL

URL は `[タイトル](URL)` で書き、タイトルがないときは `<URL>` で書く。

多くの環境は、リンクの記法を使わずに書いた URL も自動でリンクにし、空白までを URL とみなす。日本語は空白で区切らないため、URL の直後に続く全角の括弧や文字まで URL に含まれる。

悪い例:

```md
仕様は公式サイト（https://commonmark.org）にまとまっている。
```

`https://commonmark.org）にまとまっている。` までがリンクになる。

良い例:

```md
仕様は公式サイト（[CommonMark](https://commonmark.org)）にまとまっている。
仕様は公式サイト（<https://commonmark.org>）にまとまっている。
```

## 強調

強調の記号は、約物（括弧や句読点など）の外側ではなく内側に置く。

閉じる記号の直前が約物で、直後が空白でも約物でもない文字のとき、記号は閉じる記号として解釈されず、強調にならない。

悪い例:

```md
**「強調」**の
```

強調にならず、`**` がそのまま表示される。

良い例:

```md
「**強調**」の
```

## 改行

改行は、出力先での扱いを踏まえて入れる。一つの改行の扱いは環境によって異なる。

- GFM を含む多くのレンダラーでは、改行は表示されず、前後の行がつながる。GitHub の Markdown ファイルもこの扱いになる。
- GitHub の Issue、PR、コメントなど一部の環境では、改行がそのまま改行として表示される。
