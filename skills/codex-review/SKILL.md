# codex-review

Codex の指摘は、正しくても直す価値があるとは限らない。指摘を判定して結果をユーザーに報告し、修正を任されたときは直す価値のあるものだけ反映する。レビューの対象は、コード、文書、設計など、変更や成果物を問わない。

Claude Code 以外の環境で呼び出されたときは、実行せず、Claude Code が必要なことをユーザーに伝える。

## 流れ

| 依頼 | 動き |
| :-- | :-- |
| 修正も求めている（「レビューして直して」など） | 確認せずに反映まで進める |
| レビューだけを求めている（「レビューだけして」など） | 1 回のレビューと判定を報告して止まる |
| どちらか明示していない（「レビューして」など） | 1 回のレビューと判定を報告し、進め方を聞く |

進め方は、次の選択肢から聞く。

- **最後まで任せる:** 以降は確認せずに反映まで進める。
- **毎回確認する:** 今回の分を反映して再レビューし、判定を報告するたびに、もう一度進め方を聞く。
- **反映しない:** ここで止まる。

反映まで進めるときは、レビュー、判定、反映を最大 3 回繰り返す。ユーザーが回数を指定したときは、それに従う。

レビューの結果、「直す」「軽く対応する」「ユーザーに聞く」と判定した指摘がなくなるか、上限に達したら終える。上限に達した回の指摘も判定して反映し、再レビューはせず、進め方も聞かずに、その旨を報告する。

## レビューを依頼する

`Agent` ツールで `codex:codex-rescue` を呼び出す。`/codex:review` はレビューの観点や背景を渡せないので使わない。

依頼文は、1 回目は `--fresh`、2 回目以降は `--resume` で始める。レビューの間に別の Codex 作業を挟んだときは、その作業を再開しないよう `--fresh` で始める。書き込みの可否は依頼文から判断されるので、レビューだけでファイルを編集しないことを依頼文に明記する。

依頼文には、次の内容を含める。

- レビューの対象と、その確認方法（差分のコマンド、ファイルのパスなど）
- 変更の目的と、この変更で扱わない範囲
- 判断に必要な前提（利用者や権限の範囲、決定済みの方針、確認済みの事実、意図的な制限）
- 指摘ごとに、該当箇所、発生条件、影響を報告すること

2 回目以降は、前回の判定と見送った理由も伝え、新しい根拠がない限り同じ指摘を繰り返さないよう依頼する。

Codex を実行できなかったときは、代わりのレビューをせず、エラーをユーザーに報告して止まる。

## 指摘を判定する

指摘ごとに、次の順に確かめる。Codex が付けた重大度は参考にとどめ、プロジェクトの前提に照らして評価し直す。

1. **妥当性:** 対象そのものや仕様、実行結果などで、指摘が事実かを確かめる。
2. **深刻さと頻度:** 下の基準で、低・中・高を付ける。
3. **修正コストと範囲:** 修正で増える複雑さと、この変更の範囲に収まるかを確かめる。

| | 深刻さ | 頻度 |
| :-- | :-- | :-- |
| 高 | データの消失、セキュリティの侵害、本番の停止、取り返しのつかない判断の誤り | 通常の利用や読み方で起きる |
| 中 | 主要な機能の誤動作、読み手が誤った行動を取る | 特定の条件で現実に起きる |
| 低 | 軽微な不具合や分かりにくさ、簡単に回避できる問題 | 稀な条件が重なったときだけ起きる |

判定の結果を、次のいずれかに振り分ける。深刻さと頻度の組み合わせで機械的に決めず、修正コストと比べて決める。

| 判定 | 条件 |
| :-- | :-- |
| 直す | 実害が修正コストに見合う |
| 軽く対応する | 実害はあるが、提案された修正は重い。文書への記載や文言の修正などで足りる |
| 見送る | 根拠がない、深刻さも頻度も低い、修正コストが見合わない、または変更の範囲外である |
| ユーザーに聞く | 決定済みの方針や仕様を変える、またはプロジェクトの規約や決定の記録、同種のライブラリの実装を参考にしても判断できない |

反映まで進めるときは、「ユーザーに聞く」と判定した指摘を、回数によらずユーザーに聞き、回答に沿って反映するか見送る。反映まで進めないときは、判定とあわせて報告する。

深刻さが高い指摘を見送るときは、頻度が低いことに加えて、対応しなくてよい理由を具体的に示す。

## 反映する

直す指摘は、問題を解消する最小の変更で直す。誰も求めていない珍しいケースや将来のケースに備える分岐や抽象化は足さない。

反映したら、対象に応じて検証する。コードならテストや型チェックを通し、文書なら参照先や手順が正しいことを確かめる。

## 報告する

レビューの回数と、すべての指摘の判定を報告する。見送った指摘も理由を添えて載せる。

| 指摘 | 妥当性 | 深刻さ | 頻度 | 判定 | 理由 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| `docs/setup.md:12` 手順の順序が逆で、初回のセットアップに失敗する | 正しい | 中 | 高 | 直す | 手順を入れ替えるだけで直る |
| `src/bar.ts:34` 別の端末との競合でタグが消える | 正しい | 高 | 低 | 見送る | 競合の隙間が数ミリ秒で、防ぐ手段が CLI にない |

再レビューしていない修正があるときと、未解決の質問があるときは、それも報告する。
