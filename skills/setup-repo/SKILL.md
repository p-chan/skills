# GitHub リポジトリの作成と設定

これから作るリポジトリか、GitHub に作成した直後のリポジトリに使う。既存の設定との競合は扱わない。

完了条件をすでに満たしている手順はスキップする。

## 1. リポジトリを用意する

作業ディレクトリが Git リポジトリで、`origin` が GitHub のリポジトリを指していること。

Git リポジトリを新しく作るときは、初期ブランチを `main` にする。

`origin` が無い場合は、次の項目を既定値とともにユーザーに提示して確認し、GitHub リポジトリを作成して `origin` に設定する。

| 項目 | 既定値 |
| --- | --- |
| オーナー | `p-chan` |
| リポジトリ名 | ディレクトリ名 |
| 公開範囲（public / private） | private |

`origin` が GitHub 以外を指している場合は、ユーザーに報告し、扱いを確認する。

## 2. 初回コミットを push する

デフォルトブランチにコミットがあり、`origin` に push されていること。

コミットが一つもない場合は、次の選択肢をユーザーに提示して、使うメッセージを確認する。

| スタイル | 言語 | メッセージ |
| --- | --- | --- |
| Simple | 英語 | `Initial commit` |
| Simple | 日本語 | `初回コミット` |
| Conventional Commits | 英語 | `chore: initial commit` |
| Conventional Commits | 日本語 | `chore: 初回コミット` |

コミットの内容は、作業ツリーの状態で決める。

- ファイルが何もない場合: `# <リポジトリ名>` だけを書いた `README.md` をコミットする
- ファイルがある場合: どのファイルをコミットに含めるかをユーザーに確認する

## 3. マージ方式を決める

許可するマージ方式（squash / merge commit / rebase）をユーザーに確認する。

## 4. リポジトリを設定する

次の設定になっていること。

- 手順 3 で決めたマージ方式だけが許可されている
- マージ後のブランチ自動削除が有効

## 5. デフォルトブランチのルールセットを作る

デフォルトブランチ（`~DEFAULT_BRANCH`）を対象とする、次のルールを持つルールセットが有効であること。

- 削除の禁止（`deletion`）
- force push の禁止（`non_fast_forward`）
- PR 必須、承認数 0（`pull_request`）。`allowed_merge_methods` は手順 3 で決めたマージ方式に揃える

GitHub Free の private リポジトリはルールセットに対応していないので、この手順はスキップする。それ以外の理由で作成に失敗した場合は、スキップせず未完了として報告する。

## 完了報告

変更した内容と、スキップした手順・未完了の手順とその理由をユーザーに報告する。
